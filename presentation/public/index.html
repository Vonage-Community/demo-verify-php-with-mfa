What is MFA?

“Multi-Factor Authentication requires users to verify their identity using two or more independent factors before access is granted.”

MFA dramatically reduces account-compromise risk because stealing a password alone is no longer sufficient to gain access.

The Three Factors

  • Something you know — password, PIN
  • Something you have — phone (SMS/TOTP), hardware key
  • Something you are — fingerprint, face (biometrics)

Each of our three MFA methods maps to a different "have" or "are" category.

Why bother?

  • 80 % of breaches involve stolen or weak passwords
  • MFA blocks 99.9 % of automated account attacks (Microsoft, 2019)
  • Regulatory requirements — PCI-DSS, HIPAA, SOC 2

User Registration

How it works

Fill form → POST /register → Save user → 302 → /login

Stores username, a bcrypt-hashed password, and a phone number for SMS verification.

RegisterRouter — createUser


public function createUser(Request $request, Response $response): Response
{
    $body = $request->getParsedBody();

    $user = new User(
        $body['username'],
        $body['password'],   // hashed in User::__construct
        $body['phone']
    );

    UserService::save($user);

    return $response
        ->withStatus(302)
        ->withHeader('Location', '/login?success='
            . urlencode('You have been registered'));
}

Login

How it works

POST /login → Verify password → 302 → /mfa

After a successful password check the session marks the user as logged-in but not yet MFA-verified. Protected routes check both flags.

LoginRouter — login


public function login(Request $request, Response $response): Response
{
    $body     = $request->getParsedBody();
    $username = $body['username'];
    $password = $body['password'];

    try {
        UserService::login($username, $password);
        return $response
            ->withStatus(302)
            ->withHeader('Location', '/mfa');

    } catch (InvalidLoginException $e) {
        return $response
            ->withStatus(302)
            ->withHeader('Location',
                '/login?msg=' . urlencode($e->getMessage()));
    }
}

Choose Your MFA Method

  • SMS OTP via Vonage Verify v2
    Request ID → user receives code → check via API
  • TOTP (RFC 6238)
    Shared secret → QR scan → time-based 6-digit codes
  • WebAuthn / Passkeys (FIDO2)
    Asymmetric key pair stored in hardware or platform authenticator

All three are valid second factors. The app lets the user register for any/all of them and pick one at login.

SMS OTP — Vonage Verify v2

How Verify v2 Works

POST /start-verify → Vonage API
returns request_id → SMS sent
to user → POST /verify-code
{ requestId, code } → Verified ✅

The request_id ties the start and check calls together on the Vonage platform.

VerifyRouter — startVerify & verifyCode


// POST /start-verify
$smsRequest = new SMSRequest($phone, getenv('BRAND'));
$smsRequest->setTimeout(15);
$result = $this->client->verify2()
                       ->startVerification($smsRequest);

// $result → ['request_id' => 'abc123…']

// POST /verify-code  { requestId, code }
$this->client->verify2()->check(
    $requestBody->requestId,
    $requestBody->code
);

TOTP — Time-Based One-Time Passwords

How TOTP Works (RFC 6238)

  • Server generates a random shared secret
  • Secret is encoded in a QR code and scanned by an authenticator app
  • Both sides compute HMAC-SHA1(secret, floor(time/30))
  • Codes are valid for 30 seconds; server allows ±1 window

Because the server and the authenticator app share the secret, no network round-trip is needed for code generation — only for verification.

TOTPRouter — register & verify


// GET /register-totp  — generate secret + QR
$secret   = $this->tfa->createSecret();
$user->setSecret($secret);
UserService::save($user);
$qrImage  = $this->tfa->getQRCodeImageAsDataUri(
                $user->username, $secret);

// POST /verify-totp  { code }
$this->tfa->verifyCode($userSecret, $requestBody->code);

// If valid → mark session as MFA-verified
UserService::verifyUser(function () use ($userSecret, $body) {
    $this->tfa->verifyCode($userSecret, $body->code);
    return true;
});

WebAuthn — Passkeys / FIDO2

What is WebAuthn?

  • W3C standard — browser + authenticator protocol
  • Authenticator creates a key pair per site
  • Private key never leaves the device
  • Server only stores the public key
  • Phishing-resistant by design (RP ID bound to origin)

WebAuthn is the underlying API; "passkeys" is the consumer-friendly name for resident/discoverable credentials that sync across devices.

Registration & Authentication Flow

GET /web-auth-register
creation options → navigator.credentials
.create() → POST /web-auth-register
attestation
GET /auth-web-auth
request options → navigator.credentials
.get() → POST /auth-web-auth
assertion

Key Takeaways

  • MFA is table stakes for any user-facing application
  • Vonage Verify v2 gets you SMS OTP in < 10 lines of PHP
  • TOTP works offline and needs no external API at verify time
  • WebAuthn is the future — phishing-proof and passwordless
  • Offer multiple factors and let users choose
